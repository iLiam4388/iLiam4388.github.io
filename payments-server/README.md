# iLiam Stripe Sandbox
Sandbox ONLY. No real transactions. The approved Stripe planner recommended hosted Checkout and webhook fulfillment. This implementation uses server-defined inline price_data rather than creating persistent catalogue products, and an isolated test wallet. Never enable real payments by swapping keys; the server intentionally refuses live keys. Do not use this system with children's actual payment details.

## Deploy
1. Use a Node 22+ HTTPS backend host (not GitHub Pages). Deploy only the payments-server directory. Run npm install, npm test, npm start. No hosting account or deployment is created by this commit. Check provider usage charges before enabling services.
2. In the host's secret manager, set STRIPE_API_KEY to a restricted sandbox key with Checkout Session write/read and PaymentIntent read access (plus required inline price/product permissions if Stripe requests them). Set TESTER_UIDS to your approved Firebase test account UID(s), and FIREBASE_PROJECT_ID to the intended test Firebase project. For the existing website's Firebase Auth this is iliam-4d0c9. Configure Firebase Admin application default credentials securely with the minimum necessary permissions; never commit credentials. For stronger isolation, use a separate Firebase project and matching frontend Firebase Auth configuration.
3. In the Stripe iLiam Sandbox Dashboard, configure a snapshot webhook endpoint at https://YOUR-BACKEND/webhook for checkout.session.completed, checkout.session.async_payment_succeeded, checkout.session.async_payment_failed, charge.refunded. Put its signing secret in the host secret manager as STRIPE_WEBHOOK_SECRET. Do not publish the value. Restart the server with the configured secrets.
4. Put the public HTTPS backend URL into liam-payment-config.js (backendUrl). The publishable key field can remain blank for hosted Checkout. Do not paste a secret key into this public file or into .env.example. Keep the sandbox flag true.
5. Open the Store, sign in to an approved test account, and choose Get iLiam Coins. Use Stripe's test card 4242 4242 4242 4242, any future expiry, any three-digit CVC, and fictional billing details. Test a declined card using 4000 0000 0000 0002.
6. After redirect, refresh the test wallet. Verify it is credited exactly once after a paid signed webhook, and never on a decline or cancel. Retry the same event and verify duplicate delivery does not credit again. Try a refund in Sandbox and verify the sandbox balance adjusts. Normal liamWallets are never modified. Test wallet data is accessed through the authenticated backend, not client writes; no Firestore rule change is needed provided there is no permissive wildcard rule.
7. Before any live launch: obtain adult account-owner approval, confirm Stripe accepts this closed-loop virtual currency business, complete relevant privacy/child safety, consumer protection, tax, parental authorization, and refund/dispute policies, then separately design and review a live integration. Sandbox coin packs are not spendable in the normal store.

The package IDs, prices, and coin quantities are server-authoritative. The Stripe webhook secret, API key, and Firebase service-account credentials must remain private. Check hosting costs; a free tier is not a guarantee of zero charges.
